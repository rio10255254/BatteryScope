## Activity detection that works on the G14 2024, and a fairer automatic test

The overnight full test (0.18.0, G14 2024) scored activity detection at 33%:
- heavy work: 0%;
- video: 0%;
- browsing: 5%;
- idle: 99%.

The signal log showed three causes, and this release fixes each one.

**The screen counted as still while it moved.** On this OLED panel the browser presents frames directly, through multiplane overlays. The compositor's GPU use stays near 0, and its frame count near 1 per second, whatever is on screen. Detection now also looks at the foreground program's own GPU drawing, summed over all its processes, because browsers draw in a separate GPU process. A page that keeps drawing reads as reading, not idle.

**Heavy work on a few threads was missed.** Two busy threads are only 12% of a 16-thread CPU, below the 25% bar. Detection now also counts one program keeping more than 1.6 logical processors busy for 4 s. Services and Windows maintenance (updates, indexing, Defender scans) are left out.

**Video decoding read 0.** On AMD the decoder engine is named "Video Codec", not "VideoDecode". Both names now count. `gpu-engines.txt` in the lab folder lists every engine type the PC reports, to confirm it on the next test.

**The automatic test:**
- The test page follows the Windows app theme reported by BatteryScope, no longer the browser's own appearance setting. With Edge set to dark, the page stayed dark in every step, and on an OLED panel that hid what brightness and dark mode cost: brightness 40% vs 0% measured only +0.2 W.
- The brightness step reads the level back after setting it, and stops if the panel did not follow.
- The detection log gains four columns: the foreground program's GPU drawing and decoding, the busiest program, and how many processors it keeps busy. A log from an older version is kept beside the new one.

**From the same test** (± is the 95% range):
- Efficiency vs balanced mode: 1.0 W less browsing and typing, 1.5 W less on video. Heavy work was 62% slower and used 21% more energy per unit of work, which is why dynamic saving uses balanced for it.
- 60 Hz vs 120 Hz: 1.5 W less browsing, 0.7 W less on a still screen or video.
- CPU Boost off, energy preference, and background efficiency mode: no clear difference this time. Boost is already off on battery.
- The ASUS performance mode steps were skipped by 0.18; 0.19 fixed that, so the next test measures silent mode.
