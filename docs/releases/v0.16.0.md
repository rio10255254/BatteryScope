## Power goal, a 25-minute quick test, and fixes from the first full test

**Power goal (⋯ → Power goal).** Set a goal for battery power: 10 W in use and 7 W while still by default, or 12/8 or 8/6 in Settings. The page shows your average over the last 30 minutes in use and while still, how far you are from the goal, and the changes that would close the gap, ranked by watts. Where the lab has measured a change on this PC, the page shows the measured number. It also lists background programs by their current CPU power.

**Quick test (Power lab → Quick test, about 25 minutes).** It measures power mode while idle, browsing, typing, watching video and under sustained load, so detection accuracy is scored on every activity. It also measures dark mode and brightness on a light page, using 30-second blocks. The full test is still there and now takes about 1.3 hours.

**Dark mode experiment.** Switches Windows' app theme. The test page follows it, as many sites do, so the OLED saving of dark pages is measured.

**Results no longer mix different comparisons.** Runs of the same experiment are pooled only when they compared the same two settings. Example: after you switch the battery power mode to efficiency, the next run compares efficiency with balanced and becomes its own result.


The first complete automatic test on a ROG Zephyrus G14 (2024) showed what actually saves power on it and exposed several measurement problems. This release fixes them.

**What the test found**
- **Power mode "best power efficiency"** uses 2.3–3.4 W less CPU power than "best performance" in every activity: browsing, video, typing, and idle. Short tasks took 10 ms instead of 7 ms, which is not noticeable.
- **CPU Boost off** saves about 5 W while browsing or typing. It was already off on battery.
- **60 Hz** saves 0.7–1.1 W. Energy preference made no measurable difference.

**Learning fixes**
- A response is now a cost only when it is over 15% slower *and* more than 5 ms slower. Before, the 7 → 10 ms change was enough to veto efficiency mode.
- When the battery reading is too noisy, a clear CPU core saving in the same direction now counts as evidence.
- The test video's dropped-frame count is no longer used. The clip was recorded on a timer, so its frame times are irregular, and at 60 Hz the browser reported drops that a real video would not have.

**Detection fix:** on some PCs the compositor's frame counter barely moves whatever is on screen. "Is the screen moving" now comes from the compositor's GPU use, and the frame counter is ignored when it does not work.

**Automatic test changes**
- The screen-off step is removed. On Modern Standby laptops Windows goes to standby soon after the screen turns off, so the step measured standby and could add almost an hour.
- A new step measures power mode under sustained load, to show the speed cost.
- The test pages are now light, like most websites, so an OLED panel's brightness cost shows.
- Interrupted results from older versions are hidden.

建議：開啟動態省電並再跑一次一鍵自動測試（約 1.5 小時、不再測關螢幕），這次「效率」電源模式會被採用在閱讀、打字、看影片與閒置，匯出也會有偵測準確率。
