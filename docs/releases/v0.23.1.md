## Stability monitor fixes from the first real report

The first stability report from a G14 2024 showed what 0.23.0 got wrong, and these are fixed:

- **Two crashes minutes apart were merged into one.** Each start after a crash is now its own incident. The records of one crash are still folded together: the shutdown record, the stop code and the failed dump.
- **The time shown was the next start, not the crash.** Incidents now show when the PC actually went down, read from Windows' "previous shutdown was unexpected" record in Chinese, US and European date formats.
- **"Dump file creation failed" showed as a separate disk error.** It is now marked on the crash itself, as a sign that the system disk could not be written at that moment, and points to storage.
- **One app's crash loop pushed out the system's records.** In the report, 1,458 `wmiprvse` crash records filled the limit. System and app records now have separate limits, and one program keeps only its newest 20.
- **The black box recorded "lab" while the lab was only recording.** It now records a lab step only while an experiment runs.

New:
- **Drivers known to cause blue screens.** If National Instruments PCI bridge drivers (LabVIEW, PXI Platform Services: `nipcibrd`, `nipbcfk`) are installed, the Stability page warns and explains how to remove them safely. They attach to every PCI bridge and are known to cause DRIVER_POWER_STATE_FAILURE (0x9F) on sleep and wake.
- **The report summary** now lists the drivers and updates installed in the last 7 days, and each copied dump's stop code with the drivers named in its crash data.

Incidents read by 0.23.0 are read again once.

建議：更新後打開「穩定性」頁看重新整理過的時間與次數；如果出現「可能有關的驅動」，又用不到 NI 的硬體，請照頁面上的說明用 NI Package Manager 移除，不要直接停用。
