## ASUS controls that work on the G14 2024: Fn keys, keyboard backlight, Slash lighting, and services back to their defaults

0.18 read the G14 correctly but several controls did nothing. The readings you sent showed why, and this release fixes each cause. The fixes follow G-Helper's own source code.

**Fn keys work again with the ASUS software stopped.**
- On ROG laptops most Fn keys arrive as input on the keyboard's own HID interface, which only ASUS Optimization reads. With it stopped (G-Helper stops it), the keys went nowhere.
- BatteryScope now reads that interface, as well as the ATK WMI events, and greets the keyboard the way ASUS does.
- It handles every key while the ASUS software is not running, and leaves the keys to that software while it runs, so nothing happens twice:
  - brightness (Fn+F7/F8), through the firmware's own brightness key, with a fallback;
  - keyboard backlight (Fn+F2/F3);
  - Slash lighting (Fn+F4);
  - performance mode (Fn+F5);
  - touchpad (Fn+F10);
  - sleep (Fn+F11), through the firmware's sleep key, so Modern Standby is used;
  - airplane mode (Fn+F12), microphone mute, emoji panel and the ROG key.
- **On by default.** The old "handle ASUS keys" switch was off by default, which left the keys dead.
- **Fn lock with Fn+C or Fn+Esc.** The G14 has no firmware Fn lock, so BatteryScope maps F1–F11 to their hotkeys while it is on, as G-Helper does. On models whose firmware has one, that is used.
- A small on-screen display at the bottom of the screen shows what changed, in the same pixel style.

**The keyboard backlight goes over HID.** ROG keyboards ignore the ACPI backlight device. The level is now sent to the keyboard as a 0x5A feature report (TUF models still use ACPI). It is remembered and set again after sleep.

**Performance mode and charge limit are remembered, not read back.** The G14 firmware accepts both but reports nonsense for them: mode 3, and charge limit 0. 0.18 read each value back after writing it, so every change failed. Now:
- the firmware's answer is accepted, as G-Helper and the Linux driver do;
- the value is remembered and set again at startup and after sleep;
- the hardware page says "Not set" until one is chosen;
- dynamic saving and the lab can manage the mode on the G14. The lab's ASUS mode steps were being skipped.

**Slash lighting** (Zephyrus G14/G16 2024):
- on or off;
- 16 effects;
- brightness;
- pause between animations;
- off on battery.

It is detected and driven exactly as G-Helper does it.

**ASUS services:**
- **"Restore ASUS defaults (start automatically)"** brings back services that G-Helper had disabled. "Restore" in 0.18 could only put back the disabled state it had saved.
- **Stopping now uses G-Helper's list**, Armoury Crate and ASUS background services. It no longer stops every service with ASUS in its name, so the touchpad and system control services are left alone.

**Smaller fixes:**
- Power limits that read 0 (write-only on the G14) are no longer shown.
- `--asus-dump` lists the remembered settings and the report ids of every ASUS HID interface.

Unit tests compare every HID packet byte for byte with G-Helper's. Nothing here has run on the real G14 yet.

建議：更新後先在「華碩」分頁選「華碩服務 → 恢復成華碩預設」或保持停止都可以；按 Fn+F7／F8、Fn+F2／F3、Fn+F5 試試看，畫面下方應該會出現提示。若有按鍵沒反應，請把 `.\BatteryScope.exe --asus-dump | Out-String` 的結果和「最近按下的華碩按鍵」那一行傳給我。
